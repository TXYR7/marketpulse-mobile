# 打板通知（手机独立运行）

手机端行情和推送均由手机浏览器运行，不依赖电脑开机。通知围绕首板、连板接力与回封，不按S/A评分过滤，也不发评级升级通知。

## 配置

点击顶栏铃铛（或长按“星脉”）打开通知设置，默认选择“手机独立发送”。填写完整ntfy主题地址，例如 `https://ntfy.sh/your-topic`，在ntfy App订阅同一主题，然后发送测试。旧版保存的主题自动保留。

未配置ntfy时可点击“浏览器通知授权”使用系统通知兜底；配置ntfy后，网页不再同时弹系统通知或响第二遍。声音和震动仍受设备设置与浏览器支持限制。

同一主题若同时由电脑和手机发送，会收到两份。只保留一端自动推送；选择电脑来源只停止当前手机主动发送，不会远程修改电脑配置。

手机不连接券商账户。要关注持仓风险，在设置中填写六位沪深主板股票代码，多个代码以逗号或空格分隔。

## 规则

- 范围：沪深主板，排除ST和N/C新股；首板、各级接力和回封均覆盖。
- 全市场榜单默认10秒后台刷新。进入原观察区（距涨停1.5个百分点以内、成交额达标）的新票加入当天快速监控，重开后恢复。
- 前台扫描间隔5秒，实际请求耗时另计。距涨停3档以内且已进入观察区时重点提醒，低价股不会越过观察线反复触发。
- 使用精确到分的涨停价和盘口；第一档开板即可识别。触及涨停但仍有卖单时提示“尚未封板”，缺少可靠盘口时不猜封板状态。
- 只使用15秒内、带可靠时间戳的报价。临板消息包含代码、梯队、档位、现价/涨停价和行情时间。
- 临板有效期20秒，午休及收盘边界停止补发；其他核心消息2分钟，摘要1分钟。刷新不重放已处理事件，临板之后不会再补发更低阶段的冲板观察。
- 急拉比较滚动30秒内的报价；冲板/急拉的重复规则保留回落3个百分点且间隔20分钟。
- 回封按实际封板周期跟踪，不叠加20分钟冷却；刚开板不会同时叫回封。
- 封单骤减保留30%阈值，默认仅提醒当天进入临板观察的票和指定关注代码。竞价观察、全监控池封单风险默认关闭。

## 发送与后台

页面和Service Worker共用IndexedDB账本、待发记录与发送租约，避免同一设备多个页面和后台重复推送。检测记录与待发任务一起落库，失败在同一事件上补发。

临板消息优先于其他消息。单次HTTP请求4秒，总预算15秒、最多3次尝试；普通4xx不重试，网络错误/408/429/5xx可重试。429遵守Retry-After，不在限流中连续请求。状态显示ntfy接受次数、失败、过期和待发数量；“已接受”不代表手机一定已经显示。

后台扫描由浏览器的periodicSync尽力调度，注册成功不代表准时，系统暂停或关闭App后可能完全不唤醒。要抓临板窗口，保持App前台更可靠；秒板仍可能没有可观测窗口。

## 维护

`mobile-alerts.js`是页面/后台共用实现，`board-alerts.js`与桌面使用同形规则，`notify.js`与桌面发送队列对齐。`mobile-worker.js`由 `npm run build:worker` 生成，勿单独编辑。

发布前构建后台包、运行 `npm test`、执行 `scripts/bump-sw.mjs`，再提交并推送。版本号同步sw.js、version.js及HTML资源地址，旧外壳也会检查更新；核心资源未完整缓存时保留旧版。

旧通知KV账本用于一次性迁移。旧百分比封板周期状态不沿用，避免把差一档误当已封；原历史、交易、自选及主题数据保留。
